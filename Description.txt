ROVER HARDWARE DESCRIPTION

1. Central controller
- Raspberry Pi 4.
- GPIO numbers in the code and documentation use BCM numbering, not physical
  pin numbers.

2. Movement system
- The rover has 4 wheels.
- The L298N module has 2 channels controlling the left and right sides.
- IN1/IN2 control the left-side direction; IN3/IN4 control the right-side
  direction.
- According to the supplied description, IN1 is left forward and IN2 is
  left backward; IN3 is right forward and IN4 is right backward.
- The specified logic levels are HIGH = 3.3 V and LOW = 0 V.
- ENA and ENB are used for PWM speed control from the Raspberry Pi.
- There are 4 motors in total: 2 on the left and 2 on the right.
- L298N channel A (IN1/IN2, ENA) controls both left motors together.
- L298N channel B (IN3/IN4, ENB) controls both right motors together.
- Both motors on each side share direction and PWM commands. The software
  does not control individual motors on the same side independently.

Pi -> L298N connections confirmed by the user:
  L298N   BCM GPIO   Physical Pi pin   Role
  IN1     17         11                Left-side direction
  IN2     27         13                Left-side direction
  IN3     22         15                Right-side direction
  IN4     23         16                Right-side direction
  ENA     18         12                Left-side PWM
  ENB     13         33                Right-side PWM

Wiring requirements for the code configuration:
- Remove the ENA/ENB jumpers when controlling these pins through GPIO.
- Connect the Raspberry Pi GND and L298N GND to a common ground.
- Whether these wiring requirements have actually been completed has not
  been confirmed.
- Actual forward movement depends on motor wiring and mounting; it has not
  been verified through testing.

3. Piezo buzzer
- The user confirmed PWM control.
- The original description states that the BCM GPIO, model, rated voltage
  and current, and wiring circuit have not been confirmed.
- GPIO12 is also listed in the original description.
- When the buzzer should sound, its tone frequency, and its alert pattern
  have not been defined.
- The original description states that the buzzer has not yet been
  integrated into the code.

4. LCD display
- The initial description lists these statuses: Detected / Clean / Moving.
- LCD1602: 16 columns and 2 rows, connected through I2C bus 1.
- Backpack chip: PCF8574T, confirmed by the user. The RPLCD driver setting
  is "PCF8574".
- I2C address: 0x27, detected by the user's I2C scan.
- SDA1: BCM GPIO2, physical Pi pin 3.
- SCL1: BCM GPIO3, physical Pi pin 5.
- The lcdDisplay class in lcddisplay.py supports writing to either row,
  clearing either row, and clearing both rows.
- Demo mode logs LCD operations without accessing hardware. Raspberry Pi
  mode uses RPLCD and the I2C settings in config.py.
- main.py creates the display and passes it to controller.py. Cleanup
  clears the display, turns off the backlight, and closes the I2C bus.
- Actual LCD text output has not yet been verified on the Raspberry Pi.

5. Distant Sensor 
- PIN: GPIO26 - Trigger, GPIO19 - Echo
